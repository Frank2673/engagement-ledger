# 锚定记录

本文件是审计日志的**外部锚定**记录。它存在的唯一理由是补上哈希链的一个固有缺口：

> 哈希链能发现"改了某条记录"，但发现不了"把整条链重算一遍再替换"。
> 把链头哈希写进这个文件、并把本文件提交进 git 之后，
> 替换整链就会与本仓库的历史冲突 —— 这才是真正锁住日志的那一步。

## 格式

每行一条，三个字段，空格分隔：

```
<标签> <记录条数> <链头哈希>
```

标签固定为 `engagement-ledger`，便于 grep 与机器解析。
`engagement-ledger anchor --ledger <日志> | grep '^  engagement-ledger' | sed 's/^  //' >> ANCHORS.txt`

## 为什么这个文件可以进公开仓库

它**只含条数与哈希**，不含资产清单、目标名、测试结果等任何委托信息。
哈希本身是单向的：别人拿到它既不能反推出日志内容，也不能据此伪造出一条能对上的新链。

## 锚定频率建议

- 每次委托开始时（`init` 之后）
- 每天测试结束时
- 每次范围变更之后
- 交付报告之前（最后一条锚定会成为报告里引用的最终链头）
